# 读取单个本地媒体文件的信息

## 用户故事

- 作为一个要处理本地图片、视频、音频的开发者，我希望先拿到文件类型和核心信息，而不是自己分别写图片、视频、音频探测逻辑。
- 作为一个准备展示媒体详情的应用开发者，我希望一次读取宽高、时长、编码、码率和元数据，而不是把多个库拼在一起。
- 作为一个只想处理单个文件的工具开发者，我希望输入本地路径就返回结构化结果，而不是先建立媒体库或扫描目录。

## 为什么需要

媒体处理的第一步通常不是转码或编辑，而是确认这个文件是什么、能不能处理、有哪些关键属性。没有统一入口时，图片、视频、音频会各走一套读取方式，调用方要自己处理类型判断、缺字段、错误路径和元数据差异。

## 怎么解决

提供一个面向单个本地文件的信息读取能力。用户传入本地文件路径后，系统返回结构化的图片、视频或音频信息；无法识别或读取失败时，给出明确错误。

## 边界

- 只读取单个本地文件，不扫描目录、不建立媒体库、不读取远程 URL。
- 不转码、不剪辑、不生成缩略图、不解码播放预览。
- 不修改文件，也不写回 EXIF 或其他 metadata。
- 返回尽可能完整的信息；原文件缺少某些字段时允许返回空值，而不是伪造数据。
